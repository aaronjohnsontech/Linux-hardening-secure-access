Linux Hardening & Secure Access Control

This project implemented a secure Linux remote-access baseline using UFW default-deny firewall rules, SSH key-based authentication, restricted administrative access, firewall logging, validation checks, and documented rollback procedures.

Problem

SSH is a common administrative entry point. When it is broadly reachable or configured for password-based login, it increases exposure to brute-force attempts, credential attacks, and unauthorized access. The goal was to reduce remote-access risk while preserving reliable administration and recovery options.

Environment

  • Ubuntu Linux host
  • Kali Linux trusted administrative/testing host
  • UFW host firewall
  • OpenSSH Server
  • ED25519 SSH key pair

Implementation

I configured a default-deny inbound firewall baseline, allowed outbound traffic, restricted SSH access to a trusted administrative source, enabled firewall logging, generated an ED25519 SSH key, copied the public key to the Linux host, backed up the SSH daemon configuration, disabled password authentication, disabled root login, restarted SSH, and validated key-based access from a second session.

Validation

  • Verified UFW was active and enforcing the expected rule set.
  • Confirmed SSH was allowed only from the trusted administrative source.
  • Validated key-based SSH access after hardening.
  • Documented rollback steps for UFW and SSH recovery.

Security Value

The project demonstrates least-privilege access control, secure remote administration, firewall visibility, operational validation, and rollback planning. It shows the ability to harden a system while thinking about both security and service continuity.
