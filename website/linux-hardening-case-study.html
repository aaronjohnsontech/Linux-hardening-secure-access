Security objective

Reduce SSH exposure while preserving safe remote administration.

Host controls

Default-deny inbound rules, allow outbound, SSH limited to one trusted source.

Authentication

ED25519 key-based login, password auth disabled, root login disabled.

Operational discipline

Validation and rollback steps documented before treating the change as complete.

Lab context and design

This project hardens an Ubuntu host used for administration in a lab environment. The defensive design is simple and intentional: leave outbound traffic available, deny inbound traffic by default, allow SSH only from a trusted Kali host, then move SSH to key-only access and validate that recovery steps exist if anything breaks.

  • System being hardened: Ubuntu / Wazuh Manager host at
  • Trusted admin host: Kali Linux at
  • Core services: UFW and OpenSSH

1) Establish the firewall baseline

UFW default-deny baseline

The first stage was to put the host firewall into a known state, apply a default-deny inbound policy, allow outbound traffic, permit SSH only from the trusted Kali IP, enable logging, and verify the resulting rule set.

Security value: This reduces network exposure by allowing only the minimum remote administrative path needed for the task.

2) Move SSH to key-only access

Key-based authentication

Next, I generated an ED25519 key pair on the administrative host, copied the public key to the Ubuntu host, backed up the SSH daemon configuration, and disabled password-based authentication and root login.

3) Validate the change before calling it complete

Operational validation

Security hardening is incomplete without validation. After updating the SSH daemon configuration, I restarted the service, verified that it was running normally, and confirmed passwordless login from the trusted Kali host.

  • Firewall is active and logging is enabled.
  • SSH is reachable only from the approved administrative source.
  • Key-based login succeeds after password authentication is disabled.

4) Document rollback and recovery

Back-out planning

A strong hardening change includes a safe way back. I documented how to review and delete the SSH firewall rule, reset or disable UFW if necessary, and restart SSH after configuration updates.

Security Operations Value: This project is not only about hardening. It also demonstrates change discipline and the ability to leave another analyst or administrator with a recovery path.
